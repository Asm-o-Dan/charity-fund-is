### 1. Введение и назначение системы
Информационная система «Благотворительный фонд» предназначена для автоматизации операционной, финансовой и аналитической деятельности благотворительной организации. Система обеспечивает строгий учет благотворителей (доноров), поступающих целевых пожертвований, благотворительных программ/проектов, нуждающихся граждан и организаций (получателей помощи), а также целевого расходования средств фонда.

Главная цель системы — обеспечить прозрачность движения денежных средств, надежное централизованное хранение в реляционной СУБД Microsoft SQL Server, удобный и интуитивно понятный графический интерфейс (Windows Forms на C#), а также автоматическое формирование аналитических выборок для отчетности.

### 2. Стек технологий и обоснование
- **Язык программирования:** C# 12 (.NET 8.0 Windows Forms).
- **СУБД:** Microsoft SQL Server (совместимость с SQL Server 2019/2022, LocalDB `(localdb)\mssqllocaldb`, SQL Server Express).
- **Провайдер доступа к данным:** `Microsoft.Data.SqlClient` (прозрачный ADO.NET).
  - *Обоснование выбора ADO.NET:* Полный контроль над SQL-запросами, отсутствие скрытой магии ORM, использование параметризованных запросов против SQL Injection, прозрачность для защиты перед комиссией кафедры ПОВТ.
- **Архитектурный шаблон:** Многослойная архитектура (Layered Architecture):
  - **Models / DTO:** сущности предметной области и объекты передачи данных.
  - **DataAccess / Repositories:** класс `DatabaseHelper`, классы доступа к таблицам и выполнения аналитических запросов.
  - **Services / Logic:** бизнес-логика валидации, расчета балансов и подготовки данных.
  - **UI (Windows Forms):** единая главная форма с боковой навигационной панелью (Sidebar), модальные диалоги создания/редактирования записей, DataGridView с поиском, фильтрацией и экспортом в CSV.
- **Скрипты базы данных:** `CharityFund_CreateDB.sql` (создание БД, таблиц, внешних ключей, индексов, представлений, хранимых процедур и начального демо-наполнения).

### 3. Структура базы данных (ERD)

#### 3.1. Таблица `Categories` (Категории программ и помощи)
- `Id` (INT, IDENTITY(1,1), PK)
- `Name` (NVARCHAR(100), NOT NULL, UNIQUE) — наименование (Медицина, Дети-сироты, Пожилые люди, Экология, Срочная помощь)
- `Description` (NVARCHAR(500), NULL) — описание направления

#### 3.2. Таблица `Donors` (Доноры / Благотворители)
- `Id` (INT, IDENTITY(1,1), PK)
- `FullName` (NVARCHAR(150), NOT NULL) — ФИО физлица или название юрлица
- `DonorType` (NVARCHAR(50), NOT NULL) — «Физическое лицо», «Юридическое лицо», «Анонимный благотворитель»
- `ContactPerson` (NVARCHAR(100), NULL) — контактное лицо (для юрлиц)
- `Phone` (NVARCHAR(50), NULL) — номер телефона
- `Email` (NVARCHAR(100), NULL) — адрес электронной почты
- `Address` (NVARCHAR(200), NULL) — фактический адрес
- `CreatedAt` (DATETIME2, DEFAULT GETDATE()) — дата регистрации в системе

#### 3.3. Таблица `Projects` (Благотворительные проекты / сборы)
- `Id` (INT, IDENTITY(1,1), PK)
- `Title` (NVARCHAR(150), NOT NULL) — название проекта
- `CategoryId` (INT, FK -> Categories.Id) — привязка к категории
- `TargetAmount` (DECIMAL(18,2), NOT NULL) — целевая сумма сбора (руб.)
- `CurrentAmount` (DECIMAL(18,2), DEFAULT 0) — фактически собранная сумма
- `StartDate` (DATE, NOT NULL) — дата старта
- `EndDate` (DATE, NULL) — плановая дата окончания
- `Status` (NVARCHAR(50), NOT NULL) — «Активен», «Завершен», «Приостановлен»
- `Description` (NVARCHAR(1000), NULL) — цели и задачи проекта

#### 3.4. Таблица `Donations` (Пожертвования)
- `Id` (INT, IDENTITY(1,1), PK)
- `DonorId` (INT, FK -> Donors.Id) — жертвователь
- `ProjectId` (INT, FK -> Projects.Id) — проект, на который поступило пожертвование
- `Amount` (DECIMAL(18,2), NOT NULL, CHECK Amount > 0) — сумма взноса
- `DonationDate` (DATETIME2, DEFAULT GETDATE()) — дата и время
- `PaymentMethod` (NVARCHAR(50), NOT NULL) — «Банковский перевод», «Банковская карта», «Наличные», «Электронные деньги»
- `Notes` (NVARCHAR(500), NULL) — назначение платежа / примечание

#### 3.5. Таблица `Recipients` (Получатели благотворительной помощи)
- `Id` (INT, IDENTITY(1,1), PK)
- `FullName` (NVARCHAR(150), NOT NULL) — ФИО гражданина или название учреждения
- `CategoryId` (INT, FK -> Categories.Id) — профильная категория
- `Phone` (NVARCHAR(50), NULL) — контактный телефон
- `Address` (NVARCHAR(200), NULL) — адрес проживания/нахождения
- `NeedDescription` (NVARCHAR(1000), NOT NULL) — описание трудной жизненной ситуации / требуемой помощи
- `Status` (NVARCHAR(50), NOT NULL) — «На рассмотрении», «Одобрено», «Помощь оказана», «Отклонено»
- `CreatedAt` (DATETIME2, DEFAULT GETDATE())

#### 3.6. Таблица `FundExpenses` (Расходы фонда / Выдача помощи)
- `Id` (INT, IDENTITY(1,1), PK)
- `ProjectId` (INT, FK -> Projects.Id) — проект, из средств которого произведен расход
- `RecipientId` (INT, NULL, FK -> Recipients.Id) — конкретный получатель (если адресная помощь)
- `Amount` (DECIMAL(18,2), NOT NULL, CHECK Amount > 0) — сумма расхода
- `ExpenseDate` (DATETIME2, DEFAULT GETDATE()) — дата расхода
- `Purpose` (NVARCHAR(250), NOT NULL) — статья расхода (закупка медикаментов, оплата операции, продуктовые наборы, логистика и т.д.)
- `ResponsiblePerson` (NVARCHAR(100), NOT NULL) — ответственный сотрудник фонда

### 4. Реализация 5 обязательных аналитических запросов
В соответствии с заданием кафедры реализованы следующие выборки и аналитические срезы:

1. **Сумма пожертвований:**
   - Общая сумма поступивших пожертвований за все время.
   - Группировка сумм по проектам с подсчетом количества транзакций.
   - Фильтрация по произвольному диапазону дат (`DonationDate BETWEEN @From AND @To`).

2. **Активные проекты:**
   - Список проектов со статусом `Status = 'Активен'`.
   - Отображение: название, категория, целевая сумма (`TargetAmount`), фактически собрано (`CurrentAmount`), процент выполнения цели `(CurrentAmount / TargetAmount * 100)%`, оставшаяся к сбору сумма.

3. **Крупнейшие доноры:**
   - Рейтинг ТОП-доноров (физических и юридических лиц), отсортированный по убыванию совокупной суммы пожертвований (`SUM(Donations.Amount) DESC`).
   - Отображение количества сделанных пожертвований и даты последнего взноса.

4. **Расходы фонда:**
   - Сводный баланс фонда: всего собрано пожертвований, всего израсходовано средств, текущий финансовый остаток фонда.
   - Детализация расходов по проектам и статьям затрат (`Purpose`).

5. **Помощь по категориям:**
   - Агрегированные данные по категориям помощи (Медицина, Дети, Пожилые и т.д.):
   - Количество получателей в каждой категории;
   - Суммарный объем профинансированной помощи;
   - Доля категории в общем объеме расходов фонда (в процентах).

### 5. Требования к пользовательскому интерфейсу (Windows Forms)
- **Стиль:** Современный Flat-дизайн в сине-голубой гамме благотворительного фонда (SteelBlue, Navy, White, LightGray), сглаженные шрифты (Segoe UI).
- **Навигация:** Левая панель (Sidebar) с переключением между разделами без открытия кучи хаотичных окон:
  - 🏠 **Главная / Дашборд:** ключевые метрики (Всего собрано, Израсходовано, Остаток фонда, Активных проектов).
  - 🏢 **Доноры:** таблица доноров, поиск по имени/телефону, кнопки «Добавить», «Редактировать», «Удалить».
  - 📋 **Проекты:** реестр проектов со шкалой прогресса и статусами.
  - 💰 **Пожертвования:** журнал транзакций с фильтрами по донору, проекту и дате.
  - 👥 **Получатели помощи:** картотека нуждающихся и статусы рассмотрения.
  - 💳 **Расходы фонда:** реестр расходных операций.
  - 📊 **Аналитические запросы:** вкладка с 5 кнопками готовых выборок (1. Сумма пожертвований, 2. Активные проекты, 3. Крупнейшие доноры, 4. Расходы фонда, 5. Помощь по категориям) и кнопкой экспорта таблицы в CSV/Excel.
  - ⚙️ **Подключение к БД:** окно/панель проверки соединения с SQL Server, кнопка тестирования связи и возможность смены сервера.
- **Диалоги ввода:** Отдельные удобные формы для добавления/редактирования записей с выпадающими списками (ComboBox) для внешних ключей и проверкой корректности ввода (валидация чисел, дат, обязательных полей).
